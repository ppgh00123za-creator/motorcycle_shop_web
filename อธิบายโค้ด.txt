   คู่มืออธิบายโค้ดอย่างละเอียด: MOTO 160 BIKE SHOP
   สำหรับเตรียมตัวตอบคำถามและนำเสนอโปรเจกต์ให้อาจารย์ฟัง

1. ไฟล์หลักแต่ละไฟล์ทำหน้าที่อะไร
--------------------------------------------------------------------------------
- app.py: 
  เป็นไฟล์เริ่มต้นโปรแกรม (Entry Point) ของ Flask ทำหน้าที่สร้างตัวแปรแอป (app = Flask(__name__)),
  กำหนด Secret Key สำหรับระบบเซสชันและความปลอดภัย, กำหนดขนาดอัปโหลดไฟล์สูงสุด (16 MB),
  ลงทะเบียน Blueprints (auth_bp, shop_bp, customer_bp, admin_bp) และเริ่มการทำงานของเซิร์ฟเวอร์

- database.py: 
  เป็นศูนย์กลางจัดการฐานข้อมูล SQLite มีฟังก์ชัน:
  * get_db_connection(): เชื่อมต่อฐานข้อมูล instance/motorcycle_shop.db พร้อมเปิด PRAGMA foreign_keys = ON
  * init_db(): สร้างตารางทั้งหมด (users, products, orders, order_items, payments, order_status_history, receipts)
  * seed_db(): เพิ่มข้อมูลรถตัวอย่าง 20 รุ่น (ความจุ <= 160 cc) และสร้างบัญชีแอดมินกับลูกค้าเริ่มต้น
  * log_order_status(): ฟังก์ชันบันทึกประวัติการเปลี่ยนสถานะคำสั่งซื้อแบบส่วนกลาง

- routes/auth.py: 
  ดูแลระบบยืนยันตัวตน มี Route สมัครสมาชิก (/register), เข้าสู่ระบบ (/login), ออกจากระบบ (/logout)
  และมี Decorator สำคัญ @login_required และ @admin_required เพื่อควบคุมสิทธิ์ฝั่ง Server

- routes/shop.py: 
  ดูแลส่วนการแสดงสินค้าหน้าร้าน มี Route หน้าแรก (/), แค็ตตาล็อกค้นหา/กรอง (/products),
  หน้ารายละเอียดรถ (/product/<id>) และระบบตะกร้าสินค้าในเซสชัน (/cart, /cart/add, /cart/update, /cart/remove)

- routes/customer.py: 
  ดูแลระบบฝั่งลูกค้าที่ต้องล็อกอิน เช่น ยืนยันการสั่งซื้อ (/checkout), แนบสลิปโอนเงิน (/order/<id>/pay),
  ยกเลิกคำสั่งซื้อ (/order/<id>/cancel), ดูประวัติ (/orders) และดาวน์โหลดใบเสร็จ PDF (/order/<id>/receipt)

- routes/admin.py: 
  ดูแลระบบหลังบ้านของผู้ดูแลระบบ มีแดชบอร์ด (/admin/dashboard), จัดการสินค้า CRUD (/admin/products),
  จัดการคำสั่งซื้อ (/admin/orders), ตรวจสอบสลิปอนุมัติเงิน (/admin/payments) และรายงานสรุป (/admin/reports)

- utils/helpers.py: 
  ฟังก์ชันช่วยเหลือส่วนกลาง เช่น allowed_file() ตรวจสอบนามสกุลไฟล์สลิปและรูปภาพ

- utils/receipt.py: 
  โมดูลสร้างไฟล์ PDF ใบเสร็จรับเงินภาษาไทยด้วย ReportLab โดยลงทะเบียนฟอนต์ Tahoma จากโฟลเดอร์ static/fonts/


2. Route สำคัญอยู่ตรงไหน
--------------------------------------------------------------------------------
- หน้าแรก (Home): shop_bp.route('/') ใน routes/shop.py
- รายการรถและกรอง (Products Catalog): shop_bp.route('/products') ใน routes/shop.py
- สั่งซื้อและตัดสต็อก (Checkout): customer_bp.route('/checkout', methods=['GET', 'POST']) ใน routes/customer.py
- แนบสลิปชำระเงิน (Pay Order): customer_bp.route('/order/<int:order_id>/pay') ใน routes/customer.py
- ดาวน์โหลดใบเสร็จ PDF (Receipt): customer_bp.route('/order/<int:order_id>/receipt') ใน routes/customer.py
- แดชบอร์ดแอดมิน (Admin Dashboard): admin_bp.route('/dashboard') ใน routes/admin.py
- ตรวจสอบสลิปโอนเงิน (Verify Payment): admin_bp.route('/payment/<int:order_id>/verify') ใน routes/admin.py


3. หน้า HTML เชื่อมกับ Python อย่างไร (Template Engine)
--------------------------------------------------------------------------------
ระบบใช้ Template Engine ชื่อ Jinja2 ที่มาพร้อมกับ Flask:
- การส่งข้อมูลจาก Python ไป HTML:
  ใน Route จะเรียก render_template('ชื่อไฟล์.html', ตัวแปร=ค่า)
  เช่น return render_template('home.html', featured=featured_products)
- การแสดงค่าใน HTML:
  ใช้เครื่องหมายปีกกาคู่ {{ ... }} เช่น <h3>{{ product.model }}</h3> หรือ {{ product.price|currency }}
- การวนลูปและเงื่อนไขใน HTML:
  ใช้ {% for item in items %} ... {% endfor %} และ {% if condition %} ... {% endif %}
- การสืบทอดเทมเพลต (Template Inheritance):
  ทุกหน้าใช้ {% extends 'base.html' %} เพื่อดึงโครงสร้าง Navbar และ Footer จากแม่แบบหลัก ไม่ต้องเขียนซ้ำ
- คอมโพเนนต์ซ้ำ (Macros):
  ใช้ {% from 'macros.html' import product_card, status_badge %} เพื่อให้การ์ดสินค้าและป้ายสถานะสวยงามสม่ำเสมอ


4. CSS ถูกนำมาใช้กับหน้าเว็บอย่างไร
--------------------------------------------------------------------------------
- ไฟล์สไตล์ชีตทั้งหมดรวมไว้ที่ static/css/style.css
- ใน templates/base.html มีการเชื่อมโยงไฟล์ CSS ผ่านคำสั่ง:
  <link rel="stylesheet" href="{{ url_for('static', filename='css/style.css') }}">
- สไตล์การออกแบบได้รับแรงบันดาลใจจาก Thai Honda (โทนสีขาว สะอาด ดำเข้ม และแดงสด #d90429)
- รูปภาพรถกำหนด CSS เป็น .card-image-wrap img { object-fit: contain; }
  เพื่อรักษาสัดส่วนรูปรถให้เห็นครบคัน ไม่ยืด ไม่เบี้ยว และการ์ดสินค้าทุกใบมีความสูงเท่ากันเสมอกันทุกชิ้น


5. Python อ่านและบันทึก SQLite อย่างไร
--------------------------------------------------------------------------------
- ใช้ไลบรารีมาตรฐาน sqlite3
- เชื่อมต่อผ่าน conn = get_db_connection()
- ดึงข้อมูล (Query):
  rows = conn.execute("SELECT * FROM products WHERE brand = ? AND engine_cc <= ?", (brand, 160)).fetchall()
- บันทึก/แก้ไขข้อมูล:
  cursor = conn.cursor()
  cursor.execute("INSERT INTO products (...) VALUES (?, ?, ...)", (val1, val2, ...))
  conn.commit()  # ต้องเรียก commit เพื่อบันทึกการเปลี่ยนแปลงลงดิสก์อย่างถาวร
- ป้องกัน SQL Injection:
  ใช้ Parameterized Queries ด้วยเครื่องหมาย ? เสมอ ห้ามนำตัวแปรมาต่อสตริงโดยตรง


6. ระบบเพิ่มสินค้าและจัดการสต็อกทำงานอย่างไร
--------------------------------------------------------------------------------
- ฟังก์ชัน product_add() ใน routes/admin.py มีการตรวจสอบฝั่ง Server (Server-Side Validation):
  if engine_cc > 160 or engine_cc <= 0:
      flash('ระบบจำกัดเฉพาะรถจักรยานยนต์ความจุไม่เกิน 160 cc เท่านั้น', 'danger')
  และตรวจสอบ price >= 0, stock >= 0
- หากผ่านการตรวจสอบ จะบันทึกลงตาราง products พร้อมสถานะสินค้า (available / out_of_stock / discontinued)
- การปรับสต็อก: แอดมินสามารถพิมพ์จำนวนใหม่ในตารางหน้า /admin/products แล้วกดบันทึก ระบบจะปรับค่า stock ทันที
  หากสต็อกเหลือ 0 ระบบจะปรับสถานะเป็น out_of_stock อัตโนมัติ


7. ระบบเข้าสู่ระบบทำงานอย่างไร (Authentication & Security)
--------------------------------------------------------------------------------
- สมัครสมาชิก:
  รหัสผ่านจะไม่ถูกบันทึกเป็นข้อความธรรมดา แต่จะถูกแปลงด้วยฟังก์ชัน generate_password_hash(password)
  จากไลบรารี werkzeug.security ได้ผลลัพธ์เป็นข้อความแฮชที่มี Salt ปลอดภัยสูง
- เข้าสู่ระบบ:
  เมื่อผู้ใช้กรอกอีเมลและรหัสผ่าน ระบบจะดึงข้อมูลผู้ใช้จากฐานข้อมูล แล้วใช้คำสั่ง:
  check_password_hash(user['password_hash'], password)
  หากถูกต้อง จะบันทึก session['user_id'] และ session['user_role'] ('admin' หรือ 'customer')
- การตรวจสอบสิทธิ์:
  ฟังก์ชันหลังบ้านทุกฟังก์ชันจะมี @admin_required กำกับ เพื่อตรวจว่า session.get('user_role') == 'admin' หรือไม่
  หากไม่ใช่แอดมิน จะถูกปฏิเสธการเข้าถึงทันที


8. ระบบคำสั่งซื้อและชำระเงินทำงานอย่างไร (Database Transaction)
--------------------------------------------------------------------------------
- เมื่อลูกค้ากด Checkout ใน routes/customer.py ระบบจะเปิด Database Transaction:
  1) ตรวจสอบสต็อกซ้ำอีกครั้งว่ามีสินค้าพอตามที่สั่งหรือไม่
  2) สร้างเลขที่คำสั่งซื้อ เช่น ORD-20261013-0001
  3) บันทึกคำสั่งซื้อลงตาราง orders
  4) บันทึกรายการสินค้าลงตาราง order_items
  5) ตัดสต็อกสินค้าในตาราง products: UPDATE products SET stock = stock - ?
  6) บันทึกประวัติสถานะลง order_status_history ด้วย log_order_status(...)
  7) เรียก conn.commit() เพื่อยืนยันว่าทุกขั้นตอนสำเร็จพร้อมกัน
  * หากเกิดข้อผิดพลาดขั้นตอนใด จะเรียก conn.rollback() เพื่อยกเลิกทั้งหมด ป้องกันข้อมูลสต็อกเพี้ยน
- การยกเลิกคำสั่งซื้อ:
  หากลูกค้ายกเลิก ระบบจะคืนสต็อกสินค้าอัตโนมัติ: UPDATE products SET stock = stock + ?
- การชำระเงิน:
  ลูกค้าอัปโหลดรูปสลิปผ่านฟอร์ม ระบบจะบันทึกไฟล์สลิปลง static/uploads/slips/
  และบันทึกลงตาราง payments พร้อมเปลี่ยนสถานะคำสั่งซื้อเป็น "รอตรวจสอบการชำระเงิน"
  แอดมินเป็นผู้ตรวจสอบสลิปด้วยตนเอง และมีระบบป้องกันการอนุมัติซ้ำ (Prevent Double Approval)


9. ระบบสร้างใบเสร็จ PDF ทำงานอย่างไร (ReportLab)
--------------------------------------------------------------------------------
- อยู่ใน utils/receipt.py ทำงานด้วยไลบรารี ReportLab
- เงื่อนไขสำคัญ: ดาวน์โหลดได้ต่อเมื่อคำสั่งซื้อมีสถานะชำระเงินเป็น 'approved' เท่านั้น
- การรองรับภาษาไทย:
  ใช้ฟังก์ชัน pdfmetrics.registerFont(TTFont('ThaiFont', 'static/fonts/tahoma.ttf'))
  ทำให้เอกสาร PDF แสดงผลภาษาไทย วรรณยุกต์ และสระ ได้อย่างถูกต้อง ไม่เป็นสี่เหลี่ยมหรือตัวยึกยือ
- โครงสร้างเอกสาร PDF:
  ประกอบด้วย หัวกระดาษชื่อร้าน ข้อมูลเลขที่ใบเสร็จ วันที่ ข้อมูลผู้ซื้อ ตารางรายการสินค้า
  จำนวนเงิน ยอดรวมทั้งสิ้น ลายเซ็นผู้รับเงิน และตราประทับ
- ส่งออกไฟล์: สร้างในหน่วยความจำ BytesIO แล้วส่งคืนด้วย send_file(..., as_attachment=True)
