แผนภาพการไหลข้อมูล (Data Flow Diagram: DFD) — 160 ธีระ สายซิ่ง

ฟอนต์ไทยสารบัญ (TH Sarabun New) • ขอบเหลี่ยมคมไม่มีเงา • เส้นทึบฉากไม่เอียง • แยกเส้นชัดเจนไม่ทับกัน 100%

External Entity: ขอบเหลี่ยมคม ไม่มีเงา
Process: สี่เหลี่ยมขอบมน มีหัวข้อหมายเลข
Data Store: ปลายขวาเปิด แบ่ง 2 ช่อง ข้อความสีแดง (ตามรูปเป๊ะๆ)
Data Flow: เส้นทึบตั้งฉาก (ไม่เอียงทับตัวอักษร ไม่ขาด ไม่ประ แยกรางชัดเจน)
Context Diagram (แผนภาพบริบท ระดับ 0)
โครงสร้างตรงตามหน้า 1 ของเอกสาร PDF เดิม: ลูกค้าอยู่ด้านบน, Process 0 อยู่ตรงกลาง, ผู้ดูแลระบบอยู่ด้านล่าง ข้อความและเส้นแยกออกจากกันอย่างสมบูรณ์ 100%
DFD Level 1 (Diagram 0: แผนภาพระดับ 1)
โครงสร้างกระบวนการเรียงแถวตามหน้า 2 ของเอกสาร PDF เดิม: เส้นทุกเส้นเป็นแนวนอนและแนวตั้งฉาก 100% ตัวหนังสืออยู่เหนือหรือใต้เส้นอย่างชัดเจน ไม่มีเส้นเอียงทับตัวหนังสือ
DFD Level 2: กระบวนการ 1.0 — จัดการสมาชิกและเข้าสู่ระบบ
แสดงการแตกรายละเอียดของ Process 1.0: สมัครสมาชิก, ล็อกอิน, ระงับสิทธิ์, และรีเซ็ตรหัสผ่าน โดยใช้เส้นตั้งฉาก แยกรางอิสระ 100% ตัวหนังสือไม่ถูกเส้นขีดทับ
DFD Level 2: กระบวนการ 2.0 — จัดการข้อมูลสินค้าและสต็อก (พิกัด ≤ 160 cc)
แสดงการแตกรายละเอียดของ Process 2.0: ค้นหากรองรถ, ดูรายละเอียด, จัดการสต็อก เส้นทุกเส้นตั้งฉาก แยกรางอิสระ ไม่เอียงทับตัวหนังสือ
DFD Level 2: กระบวนการ 3.0 — จัดการคำสั่งซื้อและตัดสต็อก
แสดงการแตกรายละเอียดของ Process 3.0: สร้างตะกร้า, ตรวจสต็อก, คำนวณเงิน, ตัดสต็อกทันที เส้นตั้งฉาก แยกรางอิสระ ตัวหนังสือชัดเจน
DFD Level 2: กระบวนการ 4.0 — ตรวจสอบการชำระเงินและออกใบเสร็จ PDF
แสดงการแตกรายละเอียดของ Process 4.0: อัปโหลดสลิป, ตรวจสอบ, และออกใบเสร็จ PDF เส้นตั้งฉาก แยกรางอิสระ ตัวหนังสือชัดเจน
DFD Level 2: กระบวนการ 5.0 — จัดการสถานะคำสั่งซื้อและคืนสต็อก
แสดงการแตกรายละเอียดของ Process 5.0: ติดตามสถานะ, อัปเดตสถานะ, ยกเลิกและคืนสต็อกเข้า D2 แยกรางข้อมูลเป็นอิสระ 100% ไม่มีเส้นทับกัน ตัวหนังสืออ่านง่ายชัดเจน
DFD Level 2: กระบวนการ 6.0 — จัดการแจ้งปัญหาและบริการ (Support Tickets)
แสดงการแตกรายละเอียดของ Process 6.0: เปิด Ticket, ตอบกลับประสานงาน, ปิดงานคำร้อง เส้นทุกเส้นเป็นแนวนอนและแนวตั้งฉาก แยกรางอิสระ 100% ตัวหนังสืออ่านง่ายชัดเจน
พจนานุกรมข้อมูล (Data Dictionary) — ระบบร้านขายมอเตอร์ไซค์ 160 ธีระ สายซิ่ง
คำอธิบายโครงสร้าง Data Store และ Data Flow ทั้งหมดในระบบ ตรงตามฐานข้อมูลจริง 100%

1. ตารางคำอธิบาย Data Store (แหล่งเก็บข้อมูล)

รหัส ชื่อแหล่งเก็บข้อมูล ตารางจริงในระบบ คำอธิบายโครงสร้างและฟิลด์สำคัญ
D1 ข้อมูลสมาชิก users, user_ban_logs เก็บข้อมูลบัญชีผู้ใช้ (id, username, email, password_hash, role='customer'/'admin', is_banned, ban_reason)
D2 ข้อมูลสินค้า motorcycles เก็บข้อมูลรถมอเตอร์ไซค์พิกัด ≤ 160 cc (id, name, brand, model_year, engine_cc, price, stock, image_url, description)
D3 ข้อมูลคำสั่งซื้อ orders เก็บข้อมูลหัวคำสั่งซื้อ (id, user_id, order_number, total_amount, status='Pending'/'Slip_Uploaded'/'Paid'/'Shipped'/'Completed'/'Cancelled', created_at)
D4 รายละเอียดคำสั่งซื้อและการชำระเงิน order_items, payments เก็บรายการสินค้าในออเดอร์ (order_id, motorcycle_id, quantity, unit_price, subtotal) และข้อมูลการเงิน
D5 ข้อมูลการชำระเงิน payments เก็บหลักฐานการชำระเงิน (id, order_id, slip_image, transfer_amount, transfer_time, verified_by, verified_at, rejection_reason)
D6 ข้อมูลแจ้งปัญหา tickets, ticket_replies เก็บคำร้องและบริการหลังการขาย (id, user_id, subject, status='Open'/'In_Progress'/'Resolved'/'Closed', category, priority)
D7 โทเค็นรีเซ็ตรหัสผ่าน password_resets เก็บข้อมูลลิงก์รีเซ็ตรหัสผ่านชั่วคราว (id, email, token, expires_at, used)

2. ตารางคำอธิบาย Data Flow (เส้นทางการไหลของข้อมูล)

ชื่อกระแสข้อมูล (Data Flow) ต้นทาง (Source) ปลายทาง (Destination) รายละเอียดและข้อมูลที่ส่ง
ข้อมูลสมัครสมาชิก / เข้าสู่ระบบ ลูกค้า 1.0 จัดการสมาชิก ชื่อผู้ใช้, อีเมล, รหัสผ่านที่เข้ารหัส
ผลการสมัคร / ผลการเข้าสู่ระบบ 1.0 จัดการสมาชิก ลูกค้า Session Login, ผลการตรวจสอบความถูกต้อง
คำขอค้นหารถ / ข้อมูลสต็อก ลูกค้า / แอดมิน 2.0 จัดการข้อมูลสินค้า แบรนด์ (Honda, Yamaha, Vespa), ช่วงราคา, พิกัด cc (≤ 160cc)
ข้อมูลคำสั่งซื้อ ลูกค้า 3.0 จัดการคำสั่งซื้อ รหัสรถ, จำนวนที่ซื้อ, ที่อยู่จัดส่ง
ไฟล์สลิปและยอดชำระ ลูกค้า 4.0 ตรวจสอบการชำระเงิน รูปถ่ายสลิปโอนเงิน, ยอดเงิน, วันเวลาที่โอน
สถานะการชำระเงิน / ใบเสร็จ PDF 4.0 ตรวจสอบการชำระเงิน ลูกค้า ไฟล์ PDF ใบเสร็จรับเงินที่ดาวน์โหลดได้ทันที
คำสั่งปรับสถานะ / ยกเลิก ผู้ดูแลระบบ 5.0 จัดการสถานะคำสั่งซื้อ รหัสคำสั่งซื้อ, สถานะใหม่ (จัดส่ง/สำเร็จ/ยกเลิก), เลขพัสดุ
คืนสต็อกรถตามจำนวนที่จอง 5.0 จัดการสถานะคำสั่งซื้อ D2 ข้อมูลสินค้า บวกจำนวนสต็อกรถกลับคืนเมื่อมีคำสั่ง Cancelled
หัวข้อและรายละเอียดปัญหา ลูกค้า 6.0 จัดการแจ้งปัญหา หมวดหมู่ปัญหา, รายละเอียดข้อร้องเรียน
รายงานผลสรุป 7.0 จัดทำรายงาน ผู้ดูแลระบบ ยอดขายรวม, จำนวนรถที่ขายได้, รายงานคำสั่งซื้อ
